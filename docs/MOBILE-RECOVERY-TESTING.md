# 手机浏览与连续打开验收流程

本流程用于复测手机浏览、连续打开和原始副本保存。2026-11-05 已运行构建、自动回归和部分真实设备界面验证，具体证据及尚未完成的场景见 [本轮验收记录](VALIDATION-2026-11-05.md)。旧安装包不一定包含本轮修改，复测前应确认运行的是最新构建。

## 准备新版程序

1. 关闭所有 Pixora 窗口，避免请求转发给旧实例。
2. 在项目根目录运行构建；如失败，先保留完整错误输出，不继续使用旧程序验收。

```powershell
dotnet build Pixora.sln
```

3. 构建成功后启动本轮程序：

```powershell
.\src\Pixora\bin\Debug\net9.0-windows\Pixora.exe
```

4. 设置中开启复用已有窗口。连接并解锁手机，启用文件传输，在资源管理器打开含多张图片的手机目录，并保留该窗口。至少准备一张未查看的大图或长截图。

## 手动测试

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 连续双击 | 从资源管理器打开手机图 A，尚在读取时继续打开 B、C，最后停在 C | 当前窗口最终显示 C，后到的 A/B 不覆盖 C，不额外弹出旧图窗口 |
| 快速切图 | 在手机目录连续按下一张、上一张，最后停在某张图 | 标题、序号与画面一致；完成后保持最后选择，不跳到旧本地目录 |
| 跨来源切换 | 手机图片读取中，从资源管理器打开电脑本地图片 | 本地图正常打开；等待旧手机任务结束后，画面和导航目录仍属于本地图 |
| 断线错误 | 选择尚未下载的一张手机图，在读取时断开连接，或先断开再切到未读项 | 显示错误及连接/解锁提示和“重试读取”；设备未报告错误时最多约两分钟超时。已经缓存的图片仍可打开，不属于失败 |
| 重新连接 | 接回同一手机、解锁并启用文件传输；若 Windows 已关闭原目录窗口，先在资源管理器重新打开原手机目录，再点击“重试读取” | 恢复当前文件；加载期间重试按钮不可重复点击。若设备目录身份变化，应明确提示从资源管理器重新打开照片 |
| 失败后继续浏览 | 断线错误出现后，切到已下载图或打开本地图 | 可以继续使用，不会一直停留在旧错误或旧加载状态 |
| 保存副本 | 成功打开手机图，右键“文件操作 → 保存原始副本到电脑...”并选择电脑目录 | 保存成功，仍停留在手机目录；本地副本可独立打开，手机原图不变 |
| 保存取消与覆盖 | 取消保存对话框；再选择一个已有副本，分别拒绝和确认覆盖 | 取消/拒绝不改文件；确认后得到完整文件，不生成半张图 |
| 保存时切图 | 保存较大的副本期间切换图片或打开其他目录 | 已选文件的副本保持正确，新浏览会话不被切回；关闭程序时可取消尚未完成的保存 |
| 普通目录回归 | 打开本地目录，使用快捷键、缩略图、收藏、压缩和裁剪 | 本地流程仍可使用，手机专用保存菜单隐藏 |
| 关闭 | 图片读取中关闭 Pixora | 窗口正常退出；等待系统复制结束后，不残留一直等待确认的 Pixora 进程 |

保存的副本为原始字节，不会应用查看器中的临时旋转。可将同一张原图用资源管理器复制到另一个本地文件，再比较二者 SHA256；把下列占位路径替换为实际文件：

```powershell
Get-FileHash "C:\Samples\Explorer-copy.jpg", "C:\Samples\Pixora-copy.jpg"
```

预期两者哈希相同。

## 自动回归

```powershell
dotnet run --project tests\Pixora.SmokeTests\Pixora.SmokeTests.csproj
```

预期出现 `SingleInstanceCoordinator：11 项管道确认回归通过。`、`原始副本保存回归通过。`，最终为 `Smoke tests passed.`。新增用例用独立命名管道、临时文件和模拟设备来源，覆盖慢请求并发、迟到请求、关停、断线恢复、快速导航、跨目录旧结果隔离和原始副本保存；不会操作真实手机文件。完整 smoke tests 沿用已有测试和诊断日志行为。

## 记录问题

记录操作步骤、最后期望显示的文件、实际标题/序号、等待时间，以及是否断线或重连。图片错误页可使用“复制诊断信息”。构建或自动测试失败时保留完整命令输出。每次修改后重新验证相关场景，不能沿用旧构建的通过结论。
